# DATA-CHANGES —— 口径与公式的旧新对照

本版**不是**在原内核上打补丁，而是重写核算内核（`src/engine.js`，52,542 字节，不依赖 DOM），原文件保持字节级不变。下面的每一条都给出「原版怎么做 / 本版怎么做 / 影响 / 证据」。凡是我没能复现出来的，一律标成**未复现**或**未能验证**，不写成结论。

复现脚本：`node tests/original-counterexamples.cjs`，结果落盘 `tests/original-counterexamples.json`。它把原文件第 3 段内联脚本（26,213 字节的内核）单独抽出来在 Node 里驱动，`Math.random` 替换为固定种子的 mulberry32，使观察值可复现。

## 一、园区母线功率平衡

| | 原版 | 本版 |
|---|---|---|
| 守恒式 | 没有显式守恒式，缺电分支只把柔性负荷让路到「最低运行值」 | 发电 + 购电 + 放电 = 已供需求 + 充电 + 外送；每一步可核对 |
| 未供电 | 没有「未供电」概念，缺口不出现在任何一侧 | 显式计量，并把无法交付的刚性负荷（数据中心 / 公辅）按比例从「已供需求」中扣除后单独记录 |
| 柔性负荷 | 让路只让到最低值（电解锌 40 / 工厂 20 / 制氢 20 MW），剩余部分既无电源也无购电覆盖 | 阶梯让路：超充（易逝、无欠账）→ 电解槽 → 工厂 → 电解锌 → 锌全停；让路量全额记入欠账池 |
| 弃电 | 富余分配里弃电是兜底项，但放电不受「是否真有富余」约束 | 弃电同样兜底，但必须先走完「强制充电 → 柔性负荷扩容 → 自动充电 → 外送」 |

**影响（实测）**：原版在「先富余运行把柔性负荷建起来、再切成缺口」的构造下，母线两侧差 **−465.21 MW**，120 步里 **0 步**闭合；同条件下本版残差为 0。

**证据**：反例 O1（observed）；本版对应用例 P01、P05。

## 二、富余分配顺序

| | 原版 | 本版 |
|---|---|---|
| 顺序 | 超充 → 储能（charge 指令下强制）→ 电解锌 → 工厂 → 制氢 → 弃电；「放电」指令在富余时仍按容量上限放电，多出来的电只能进弃电 | 强制充电 → 柔性负荷扩容（计划之上）→ 自动充电 → 外送 → 弃电；**不允许放电与弃电并存** |
| 强制充电 | 缺电分支下 `gridBuy = need − stP`，充电功率计入购电；富余分支下强制充电可能挤掉柔性负荷扩容 | 强制充电是操作员显式指令，优先于把柔性负荷推过计划值；购电充电默认关闭（`GRID.allowGridCharge=false`），开启时**显式增加购电**，不隐含 |
| 自动充电位置 | 与柔性负荷扩容竞争 | 排在扩容之后，避免储能抢走本可减少欠账的电量 |

**影响（实测）**：原版在「16 m/s 大风 + 放电指令 + SOC 80%」下，**200/200 步**同时出现放电（均值 150 MW）与弃电（均值 281.76 MW）。

**证据**：反例 O2（observed）。

## 三、氢物料平衡与储罐约束

| | 原版 | 本版 |
|---|---|---|
| 库存结算 | `h2Kg = clamp(h2Kg + (产氢 − 合成用氢 − 燃料电池用氢)·dt, 0, 罐容)` | 事前约束：接近满罐时先压低制氢功率，不用末端截断 |
| 越界处理 | clamp 静默截断，没有溢流账 | 无截断路径；导出账本给出 `balanceKg` 余差，非 0 即可判定不闭合 |
| 账本可自查性 | 未导出氢的起始库存，无法只凭导出数据核对质量平衡 | 账本含 `startKg / producedKg / toAmmoniaKg / toFuelCellKg / balanceKg` |

**影响**：原版的滞后守卫（「接近满罐时按上一步产氢量压低制氢」）恰好在正常参数下把库存稳在界内，我**没有**复现出 clamp 真正吞掉质量的步（见反例 O3，标注 not-reproduced）。所以这里如实写：原版的问题是**存在一条静默截断路径且账本不可自查**，而不是"每次都算错"。

**证据**：反例 O3（not-reproduced，附两个构造的实测数）；本版导出账本氢段余差在七个情景 24 小时推进中为 0（`tests/browser-soak-*.json`）。

## 四、合成氨公辅负荷的时序

| | 原版 | 本版 |
|---|---|---|
| 时序 | 本步的 `loadMW` 里用的是**上一步**算出的 `nh3Aux`；制氢功率突变时公辅负荷不跟着变 | 每步内部先做耦合迭代（辅助用电 ↔ 氢产量 ↔ 电解功率 ↔ 燃料电池），最多 14 轮，收敛后再结算 |
| 未收敛 | 无此概念 | 记 `converged=false` 并推事件，不假装收敛 |

**影响（实测）**：制氢功率从 161.61 MW 一步降到 20 MW 时，原版本步实际计入的公辅用电是 **9.9733 MW**（按上一步产氢量），而按本步产氢量应为 **2.1609 MW**，单步差 **7.81 MW**。

**证据**：反例 O4（observed）；本版对应用例 P06。

## 五、跨日欠账

| | 原版 | 本版 |
|---|---|---|
| 跨日 | 日切换时 `debtZinc = debtFac = debtPem = 0`，未履行的计划直接注销 | 跨日**结转**（`debtZincCarry` 等），不清零 |
| 字段 | 状态对象里没有任何结转字段 | 有 |

**影响（实测）**：原版跨日前欠账合计 0.1171 MWh，跨日后 0 MWh，且状态字段里搜不到任何 `*Carry`。

**证据**：反例 O6（observed）；本版对应用例 F03。

## 六、排放与政策对标口径

| | 原版 | 本版 |
|---|---|---|
| 当日排放累加 | `dCo2 += max(0, 风光核发电量 − 弃电)·dt·电网因子` —— 排放量正比于**零碳发电量** | 按来源账本分项：外购电间接排放 = 外购电量 × 省级因子；燃气直接排放单列 |
| 燃气 | 燃气发电进功率平衡，但没有任何燃气排放项（全源码搜不到） | 燃气因子默认空白；填入前燃气电量单列「因子待配置」，不计入排放合计，也不追溯为零 |
| 碳排放强度 | `gridBuy·因子 / (总负荷 × 0.1229)`，分母是把电按 0.1229 kgce/kWh 折成 tce | 不输出综合能耗或碳强度结论 |
| 政策对标 | 用 0.1229（电力**当量值**折标系数）直接算综合能耗，未标注用的是当量值还是等价值 | 一律显示 **待核算**，并列出缺的参数（年度综合能耗·等价值口径 / 非电能源边界 / 非电燃料因子） |

**影响（实测）**：原版在「购电 0 MW、燃气发电 50 MW」下，期内购电为 0 而当日排放 3.4407 t —— 说明这个排放量不来自购电；同时燃气相关标识在源码里出现 9 次、燃气排放项出现 0 次。

**证据**：反例 O5（observed）、O7（unverified，属代码级观察：0.1229 出现 2 处，均未标注口径与年份）；本版对应用例 C01–C05。
