# v18 调度、履约与计量交易

入口：`dist/Net-Zero-grid-premium.html`，可离线打开。v17 保留在原目录，没有覆盖。

## 如何查看

1. 顶部“情景”选择八类运行条件，切换会重新开始仿真；左侧“重置情景”可重复同一情景。
2. 左侧“履约与调度详情”查看电解锌、制造任务、氢库存、储能原因和购电分项。
3. 点击 Token 楼“计量与交易”，查看本次累计产出、能源来源示意和交易框架。
4. 在交易框架创建 100 万 Token 模拟需求，推进仿真后确认模拟交付。价格留空时不产生收入数字；已确认记录不能重复结算。
5. 云参观 → 情境演示提供与顶部一致的八类情景。对比原固定顺序与履约优先调度，同时披露任务和期末库存。

## 调度规则

- 任务按运行起点每 24 h 生成：电解锌 2400 MWh、制造 1200 MWh。均为等效生产用电任务，不是实物产量或真实订单。
- 临期与富余情景含标明来源、形成时间和期限的预设待完成任务。
- 任务按截止时间分配已完成量。超额运行单列；逾期是待完成量的子集，历史违约不会因后来补完而消失。
- 目标功率考虑任务累计所需平均功率与 1 h 提前裕量，受爬坡和容量约束。关键负荷、生产保障需求及制氢最低运行需求先由电源、可用储能和购电保障，再压减可调整部分。
- 储能自动模式备用目标为 25%，硬下限 10%、上限 95%。操作员强制放电可用到硬下限，界面如实记录备用不足。
- 富余电先恢复备用目标，再按工业任务期限补产，然后按下游和目标库存制氢、继续储能充电、外送、弃电。
- 制氢目标库存 3000 kg，按约 2 h 库存补充窗口加上下游耗氢推算需求；受设备容量及罐容约束。没有固定用电欠账。
- 购电默认上限 400 MW，外送默认 0 MW。外送能力保留在配置中；不能将其演示为已获得并网许可。
- 无法完成任务时保留逾期和受限提示。额定能力估算仅是上界检查，未预测未来天气、停机和爬坡，不能据此保证交付。

## 数据与计量

- `engine.taskSnapshot()` 是任务、累计服务计量与模拟订单读取接口；`exportLedger().fulfillment` 导出完整运行账本。
- `exportLedger().plan` 按园区提供计划、完成、待完成、逾期和额外运行（MWh）；氢库存独立以 kg 表达。
- 老字段 debtZinc/debtFac 仅为待完成任务的兼容别名，debtPem 不再累计制氢用电欠账；不应将它们解释为历史生产用电差额。
- 算力统一采用每 MWh IT 用电 16.67 亿 Token 的原演示系数，输入与输出尚未拆分。按实际供电比例折算，不能视为真实吞吐或客户交付。
- IT 与数据中心总电耗分别计量。来源比例按园区母线混合比例分摊，是模型示意，并非逐路电表溯源。初始库存保持未知来源。
- GPU·h、数据用量、实际请求成功率、业务能耗分摊、真实价格均待配置。模块内一小时假设折算器不写入订单或收入账本。
- 模拟订单在当前运行内预留互不重叠的计量区间；交付需人工点击确认，重复确认不会新增金额。金额为模拟结算，不接入支付，不发行 Token 资产。
- 场景切换生成新运行标识，任务、计量、告警及模拟订单同步重置。云参观使用隔离内核，退出后恢复主场景。

## 修复的基础问题

- 合成氨爬坡以物理步前的运行值计算，避免迭代求解重复累加爬坡。
- 风况与车流使用独立随机源，避免生产策略间接改变天气序列，破坏对比公平性。
- 1× 播放保存不足一秒的余量，暂停冻结计量。

## 验证

- `tests/dispatch-v18.test.cjs`：新版 13 项验收，包含八情景 24 h、连续三日、不可完成任务、模拟结算幂等与隔离。
- `tests/engine.test.cjs`：29 项旧策略物理回归。该套测试明确关闭新版调度，检验原物理能力；新版行为由前述测试覆盖。
- `tests/dispatch-browser.cjs`：15 项浏览器验证，包含八情景入口、窄屏、订单重置、同条件推演、退出恢复、无运行错误和离线加载。
- `node build.cjs --verify`：13 项离线自包含检查。

未接入真实订单、计费、电价优化、气象预测或现场控制。本轮提供可解释的规则与核验框架，不宣称求得全局最优。
