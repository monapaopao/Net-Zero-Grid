# v21.2.0 园区车辆

本目录单独管理车辆重设计；v21.1.1 是回退基准。项目入口仍为根目录 `index.html`，使用 Three.js r187 / WebGPU。没有 Blender 或外部模型、图片依赖。

采用 anatomy 的真实部件、结构接合、曲面与局部检查方法。实际车辆是 Three.js 网格，未使用该技能的 SVG 渲染器或测试版 3D 运行时；下面的几何检查也不是 anatomy SVG 的遮挡审计。

## 建模与预算

- 每类分为底盘、轮组、车体、玻璃、灯具、附属设备、接口；具体部件清单由 `model.js` 的命名部件直接生成，数量见 `evidence/geometry.json`。
- 轮拱从车体下边界实际挖出，不靠在车身外贴黑色圆片遮挡。轮胎有胎肩，轮毂为凹腔与辐条。大形体倒角，细部按材质/层级合并。
- 风挡与灯具置于外表面，踏板避开轮胎；罐体在驾驶室后结束。材质区分车漆、玻璃、橡胶、金属和灯罩，玻璃不使用多层透明或透射通道。
- 同类复用几何体、同材质使用实例，保留 instanceId 到车辆的映射。精致档 95 m、标准档 55 m 内显示细节；兼容档隐藏细节。采用实例批次视锥剔除，不增加运行时曲面重建、每帧纹理更新或渲染通道。
- 细节按共享批次判断距离，同批次内有车靠近时会显示该批次细节，不是逐车独立 LOD。细节淡化和完整车身多级 LOD 未纳入此次实现。

## 源码和构建

`model.js` 是纯部件数据；`geometry.js` 创建车体、轮胎、封头等几何；`build.cjs` 将其接入原有车辆布局、线缆与选择模块。历史 v20 源码不改写。

```powershell
node visual-upgrade/build.cjs
node visual-upgrade/webgpu/build.cjs
node visual-upgrade/vehicles/test.cjs
node visual-upgrade/vehicles/check.cjs
```

`test.cjs` 检查 8 类几何的有效性、实际轮拱开口、接地、车间边界、净空、LOD 恢复和仿真状态。`check.cjs` 在真实 WebGPU 页面检查车辆射线选择、全部信息卡及充电端点，与 `evidence/before.json` 比较实例数据，并保存同机位截图。独立近景截图为检查用途：隐藏其他场景物体，增加中性地台，保留原场景光照与材质；园区实景见 campus/charge/parking 图片。

基准页面来自 `v21.1.1:visual-upgrade/webgpu/dist/多园区-v20-r187-WebGPU.html`，复制到被 Git 忽略的 `tmp/vehicle-baseline/v21.1.1.html` 后，可运行：

```powershell
node visual-upgrade/vehicles/check.cjs --baseline --file="E:/项目绝对路径/tmp/vehicle-baseline/v21.1.1.html"
node visual-upgrade/vehicles/bench.cjs
```

性能比较按 before / after / after / before 顺序，固定 1440×810、DPR 1、精致档、暂停日景与机位，每机位预热 240 帧、记录 300 帧。数据见 `evidence/performance.json`。帧间隔包含浏览器调度与垂直同步，不代表所有机器都能稳定 60 FPS。

本机交替采样结果：三个机位中位帧间隔均约 16.7 ms；总览 P95 前后均约 33.4 ms；充电与停车区升级后约 16.8 ms，原版两轮在 16.8–33.2 ms 之间。采样有调度波动，不将这个差值视为稳定的加速承诺。总览绘制调用从 3381 降至约 3331，充电区从 1609 降至 1558，停车区从 1434 降至约 1396–1397；场景三角形数增加约 0.2%–1.2%。总览仍有掉帧，此次没有把整个园区优化为稳定 60 FPS。
