# 面向普通电脑演示的性能调整方案

2026-11-10，根据用户在精致档出现卡顿的反馈补充检查，随后按用户确认实施 1–5 步优化。下面“已定位的问题”“补测结果”是优化前诊断，当前实现和结果见文末。

## 已定位的问题

- 标准档像素倍率上限 1.25，精致档 1.75。在设备像素比足够高时，精致档实际像素数量约为标准档的 1.96 倍。
- 阴影贴图从 1024×1024 提高至 2048×2048，阴影贴图像素数变为四倍；这不代表整帧耗时必然四倍。
- 精致档增加深度 AO、离屏渲染和合成，夜间另有泛光模糊。
- 精致档开启全园区部分环境细节，而非只提升当前关注区域。
- 新版五类车辆共享几何数据，但 19 辆车仍由多个普通 Mesh 单独绘制，没有车辆 LOD。共享数据减少资源重复，不等于合并绘制调用。
- 原车辆实例通过零缩放隐藏，仍保留在原实例批次中；后续应压实实例列表或拆分批次，减少无效顶点处理。
- 手动指定画质会关闭原有的自动降档。原有自动模式又只在低于 30 FPS 时降档，不适合以平稳 60 FPS 为目标的演示。

## 补测结果

RTX 5070 Ti，Chrome headless / ANGLE D3D11，1920×1080 CSS 视口，设备像素比 2。保留正常页面侧栏，运行仿真，围绕充电站移动镜头；各配置先稳定 2.2 秒，再采样约 5 秒。下列自动化结果用于定位瓶颈，不能当作用户前台浏览器的准确帧率或普通设备承诺。

| 配置 | 实际画布尺寸 | 中位帧间隔 | P95 帧间隔 |
| --- | --- | ---: | ---: |
| 标准 | 1787×1115 | 16.7 ms | 16.8 ms |
| 精致 | 2502×1561 | 133.5 ms | 650.1 ms |
| 精致，仅禁用后处理 | 2502×1561 | 49.8 ms | 283.8 ms |
| 精致，仅把像素倍率改为 1.25 | 1787×1115 | 16.7 ms | 16.8 ms |

详细数据在 `web/evidence/motion-profile.json`。这是短时、固定顺序的隔离测试，不能精确分摊各项 GPU 时间，但足以复现高 DPI 下的明显卡顿，并说明降低内部渲染像素量应当优先。之前 1440×810、DPR 1、静止机位的数据不能用于证明高 DPI 动态演示顺畅。

## 建议实施顺序

1. **控制像素与后处理预算**：演示默认标准档；精致档倍率上限先降至 1.25，普通档优先 1.0。增加总像素上限，避免 4K 屏幕使内部渲染分辨率失控。HUD 和文字继续保留原生清晰度。日间优先用已有地坪 AO 烘焙，精致档 AO 改为低分辨率计算并调低采样；夜间泛光按需开启。
2. **车辆合批和距离分级**：按原型和材质使用实例化或适当合批；车漆颜色用实例属性，牌照做图集，保留 instanceId 到业务 ID 的映射。制作近、中、远三个网格层级，远处轮胎花纹、轮毂细节和面板缝不再使用密集几何。分块管理实例，避免整园区同类对象共用一个过大的剔除包围盒。
3. **限制阴影与精细内容的范围**：全园区概览用低模；只有当前观察区域进入精细状态。实时投影优先保留建筑轮廓、车身、棚架；小螺丝、轮胎纹和细小叶片不单独投影。静态光照固定时缓存阴影，在太阳方向、拆解状态、投影物体或阴影覆盖区域变化时更新；风机等动态对象仍需维护自己的更新策略。
4. **按区域扩展整个园区**：每个区域提供低模与精细资产，接近时加载/显示精细层，离开后降级；夜间局部灯、室内结构和标签更新也按区域启用。先给充电站确立预算，再升级其他园区，不把各区域最高精度同时常驻绘制。
5. **动态演示验收**：恢复具有迟滞的自适应分辨率，持续变慢时先降低内部像素量，再降低 AO/阴影；恢复条件比降级条件更保守，避免反复跳档。检测图形上下文和实际 GPU，补测首次着色器编译、导览转场、日夜切换、拆解、1080p/高 DPI/4K，以及普通集显。以固定导览中的中位和 P95 帧时间、超 50 ms 长帧数量验收，不能只看静止时的平均 FPS。

优先目标是：本机运动演示接近稳定 60 FPS；普通电脑 1080p 默认模式以稳定 30 FPS 为底线、尽量达到 45–60 FPS。这些是待验证的验收目标，尚未在普通集显实机上得到证明。

## 已实施的性能优化

1. **像素与后处理预算**：精致倍率上限 1.25、标准倍率上限 1.0；精致内部画布上限约 185 万像素，标准约 135 万。4K 屏幕仍按内部预算渲染并缩放输出。取消离屏 4× MSAA，使用轻量边缘平滑；AO 独立半尺寸、8 个方向采样并按深度权重上采样；泛光为四分之一尺寸、两次分离模糊，日间跳过泛光通道。保留 HDR/PBR 和日夜灯光。
2. **车辆实例化与 LOD**：按车型、材质、距离层级实例化，车漆使用实例颜色；19 辆车的前后牌照使用一张图集、一个实例批次。保留 `instanceId → vehicleId` 点击查询。Blender 导出强制应用简化修改器；实际 GLB 中的车辆原型面数为近景 159,038、中景 28,609、远景 2,760。近景阈值约 32 m，中景至约 120 m，切换使用迟滞。原车辆批次压实有效实例并恢复 ID 对应，避免只用零缩放隐藏。
3. **局部阴影**：近景收紧阴影覆盖范围，小硬件、轮毂细节和细小叶片减少投影；充电站固定视角缓存太阳阴影，目标区域、模型切换、LOD、柜门拆解或光照方向变化时刷新；其他区域含风机等动态对象，以约 10 Hz 更新阴影，保留主画面正常刷新。
4. **区域细节管理**：园区精细环境、风光场站精细环境、公园设施及微细节、光伏电气细节按关注位置和约 155 m 半径筛选；总览保留基础层。LOD 和区域过滤独立于画质按钮，精致档也只绘制当前可辨识的细节。离线单文件仍内嵌所有资源，本次没有改成网络分块下载。进入数据中心嵌入视图后暂停被遮住的园区绘制，退出后恢复。
5. **自适应与验收**：手动精致档也保持帧时间监测；连续两段慢帧窗口后逐级缩小内部画布，高压力时调整 AO 和阴影预算。持续有余量约 12 秒后只恢复一级，避免来回跳变。界面保留“精致”选择，并标注“自适应 / 流畅优先”。增加实际高 DPI、4K 连续运镜、车辆射线点击、完整接待导览及外部主线程压力测试。预编译使用与后处理一致的线性目标，并预热柜体半透明材质。

## 优化后验证

`web/evidence/performance-checks.json` 记录了 1920×1080 / DPR 2 与 3840×2160 / DPR 1 的全景、入口日景、入口夜景、工厂、园区总览五组连续运镜。全部保持 `quality: high`，P95 约 16.8 ms。185 万像素预算限制的是内部画布，不是浏览器窗口尺寸。

1080p / DPR 2 下，充电站全景约 713 次绘制调用、304 万个绘制三角形；入口近景约 840 次、319 万三角形。统计包含当前实际发生的阴影通道，并随镜头变化。场外/园区主体已有的几何仍贡献较多三角形，后续扩大写实资产时应继续遵守当前区域预算。

人工压力测试每帧额外占用主线程 38 ms，确认预算收缩并在移除压力后恢复一级，期间画质状态始终是 `high`。这是机制验证，不能模拟普通集显的 GPU、显存或驱动。

`web/evidence/tour-performance.json` 为完整 180 秒接待导览的记录，包含楼内视图和园区恢复，按镜头记录中位、P95、最大帧时间及超过 50 ms 的次数。本次约 10,827 个采样帧的中位为 16.7 ms、P95 为 16.8 ms；超过 50 ms 的帧有 4 个，其中首次载入楼内视图的最大长帧为 300 ms。SST 首次切换经预热后该镜头最大约 16.8 ms。运行期间的少量首次进入/转换长帧应与稳态 P95 一起评估，不能用平均 60 FPS 隐去。

SST、车辆与接待逻辑、光流方向/零流、离线回退和标签按钮另由已有功能检查覆盖。尚无普通集显和移动设备实机记录。
